# Lane Autonomy - non-gated menus auto-proceed

Adopted 2026-08-19 (pipeline-upgrade grill, upgrade 4). History: `research/dev-workflows/2649-rules-history/archive/lane-autonomy.md`.

**A lane only BLOCKS on a question when the answer is genuinely Zaal's.** A question is ZAAL-GATED when ANY is true: money moves or spend is committed; anything goes public or outbound; the action is irreversible (delete, on-chain, permaweb, key rotation); the answer is a fact only Zaal knows; Zaal asked to be asked.

Everything else (scope picks, ordering, which reversible approach, whether to include a PR-only sub-task):
1. Take the RECOMMENDED option.
2. LOG it where Zaal will see it: one line in the lane's report + the board card note ("auto-proceeded: <choice>, override anytime").
3. Keep working. Every auto-taken choice must be cheap to reverse.

Guards: when in doubt whether it is gated, IT IS GATED. A non-gated choice that leads to a gated action still stops at the gate. The log line is mandatory. This governs semi-attended lanes, not interactive sessions where Zaal is present and typing.
