### Doc 2273 (Part 2): The Reddit Fix Was a Backup File for a Month

**Category:** infrastructure / tooling

`zao-fetch-reddit.sh` v4 (OAuth-first) was written on 2026-07-12 and saved as `bin/zao-fetch-reddit.sh.bak-redlib`. That `.bak-redlib` suffix reads as "superseded" — so nobody found it while two lanes each spent an hour hitting the walled redlib path.

Measured tonight (not assumed):
- Token endpoint is reachable (401 + JSON response)
- `oauth.reddit.com` 403s with an HTML block page for unauthenticated requests
- Public `.json` returns `text/html`
- 0 of 3 sampled redlib instances answered 200

**What this means:** OAuth CAN run unattended (client_credentials flow, no user password needed). Registration needs Zaal's reddit login (attended, one-time). No credential was invented or stored. What's unproven: that a valid token clears the 403 — that needs a real credential.

### Doc 2272: The Spec for Keeping Failed Work + a Silent Bug Named

**Category:** ZOE / work-loop / build spec

Doc 2271 (PR #3067, still open) found that `work-loop.ts` deletes failed work. Doc 2272 adds a **second, worse failure path** that 2271 missed:

When `runResearch` returns an empty string, `reportFor` is inside the `if (firstOutput.trim())` block — so nothing is sent anywhere. The code then:
1. Deletes the work item from the queue
2. Charges it against the daily cap
3. Emits a receipt with `resultType: 'success'`

This is a **silent success** on a failed run. The code's existing comment says "Remove from queue even on error to avoid infinite retry loop" — that's CORRECT. Dequeuing is right. Deleting the evidence is the bug.

**Spec (PR #3076):** Park rather than delete. Append-only `work-parked.jsonl` with fold-per-id, a `blocked` state, the stage it died at, operator-only re-entry. A parked item costs nothing. The fold-per-id design comes from Peter (doc 2271) — avoids the status-only append dropping fields a resume needs.
