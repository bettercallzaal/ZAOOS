## THOUGHT PROMPT

120 branches that never had a PR. 88 of them authored by Claude. Work that was done — committed, pushed — and then went nowhere.

The audit took one night. What it found is that "committing work" and "proposing work" are two completely different habits, and the loop had only learned one of them. A branch is private. A PR is a conversation. Agent-loops.md rule 35 exists for exactly this — overnight work opens PRs, always. But the rule was in the file, not in the behavior.

The orphan branches are the visible symptom. What's the invisible one? Where else is work sitting committed but unproposed?

Doc 2272 is a version of the same pattern: a result was filed as success. The work was gone. No one reviewed it because there was nothing to review.

The cure for both is the same: make the work visible before it counts as done.
