## What the PDF says that we should NOT adopt

- **LLM-as-judge sensors.** PDF Table XV lists "no inferential sensors" as a mistake. Our `loop-evals.md` already has the fresh-context evaluator for high-stakes only, and `code-over-inference.md` says the same judgment every time is a script. Keep computational-first; the PDF agrees on order (IV.E) and disagrees only on whether to add the inferential tier at all.
- **Its numeric defaults** (Table IV, Template 2). Recorded above as the PDF's; ours are UNSET.
- **Its "seven days to production" build path** (Table XI). We are past day 7 on every layer; the useful artifact is the Scale Gate (completion >= 80% without manual correction, no task over budget, at least one correct escalation), which is `loop-evals.md`'s reliability number in different words.
- **The seven-layer X article** (routing + feedback as separate layers). Routing is `CLAUDE_CODE_SUBAGENT_MODEL=haiku` in `settings.json` env plus the `zao-build-orchestrator` / `zao-builder` / `zao-formatter` agent tiers; feedback is the ratchet, which is layer 1. No new layer needed.
